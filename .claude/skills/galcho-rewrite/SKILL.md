# ギャル庁 記事の加筆・リライトスキル

すでに公開（または予約済み）の記事に手を入れるときに呼ぶ。新規記事の整形は [[galcho-article-format]] のほう。

## 📖 このルールが生まれた背景

2026-09-27、AdSense の「有用性の低いコンテンツ」対策で既存記事の加筆を始めたときに決めたルール。

**加筆は「文字数を増やす作業」ではなく「読者が得する情報を足す作業」。**
同じことの言い換えで水増しした記事は、むしろ評価を下げる。

## 🧭 作業前に決めること

- **1バッチの加筆対象は最大10本**。それ以上あるときは分割する
- **同じテーマの記事を同じバッチに入れない**（台風ネタなら1バッチ1本）
  - 同じ解説文が複数記事に入って**重複コンテンツ**になるため
- サブエージェントに投げるときは**触ってよいファイルを明示する**
  - 同じファイルを2体が同時に触ると壊れる
  - 「このファイルだけ編集。他は読むだけ」と書く

## ➕ 何を足すか（加筆の中身）

足すのは次の4種類だけ。**文字数の水増し（同じことの言い換え）は禁止**。

1. **前提知識・定義**
   - 例: 夏日／真夏日／猛暑日の定義、1バレル＝約159L、〇〇法の対象範囲
2. **経緯・比較**
   - 例: 2019年の台風15号との被害比較、法改正がここまで来た経緯、前回との数字の差
3. **読者が行動できる情報**
   - 例: 手続きの期限、応急手当の手順、自分が対象か確認する方法、問い合わせ先の種類
4. **あーしの考察 ＋ 内部リンク**
   - 💎ぶっちゃけポイント（insight）であーしの視点を足す
   - 過去記事への内部リンクを**3〜6本**

### 構成の型を使い回さない

- 毎回 gov-block → compare → insight の**同じ順番にしない**
- その記事に合う部品だけ使う（定義が要る回だけ gov-block、比較がある回だけ compare）
- 全記事が同じ型だと「量産サイト」と見られるリスクがある

## 🚨 厳守事項

- **数字・固有名詞・日付は WebSearch で裏を取る**
  - 取れないものは**書かない**、または「〜とされてる」「〜が多い」に弱める
- **記事の公開日より後の出来事を足さない**
  - 日付は絶対表記（「今日」「昨日」「先週」は使わない → 「2026年9月20日」）
- **`aashi` は1文字も変更しない**（ユーザーの手書き部分）
- **`date` / `publishDate` / `categories` / `source` / `source_url` は変更しない**
- **`**` を 「」『』（）の隣に置かない**。強調は `<strong>` を使う
  - 例: ❌ `**「セリフ」**って` → ✅ `<strong>「セリフ」</strong>って`
- **吹き出しは kasumi と aashi だけ。kouhai は使わない**
  - kasumi は硬いお役所口調・絵文字なし（口調サンプルは [[galcho-article-format]] 参照）
- **内部リンクは実在するファイル＋リンク元より前に公開された記事だけ**
  - 未来の記事にリンクすると公開時点で404になる
- **アフィリエイトのスニペットは加筆時に勝手に入れない**
  - プレースホルダー `<!-- AFFI: 商品キーワード -->` のみ置く（→ [[galcho-moshimo-affi]]）

## 🩹 本文を直したときの後始末

### front matter の整合を取る

本文の事実を訂正したら、以下が本文と矛盾しないように直す:

- `title`
- `lead`
- `points`
- `tweet`

（本文だけ直してリード文が古い数字のまま、が一番やりがちな事故）

### 訂正を記事に明記する

**公開済み記事の事実を訂正したら、記事末尾に訂正を明記する。**

```markdown
※2026年9月27日訂正：ガソリン税の税率を修正しました。
```

これは `/editorial-policy/` に書いた
「誤りが分かったら直して、直したことが分かるようにする」という
**読者への約束**を守るため。こっそり直すのはナシ。

### lastmod を入れる

加筆・訂正した記事は front matter に `lastmod` を追加する（更新日をサイトとサイトマップに出すため）。

```yaml
date: 2026-09-10T07:00:00+09:00        # ← 変えない
publishDate: 2026-09-10T07:00:00+09:00 # ← 変えない
lastmod: 2026-09-27T12:00:00+09:00     # ← 加筆した日を追加
```

## ✅ 終わったあとの検証

```bash
cd /d/Code/gal/site && hugo --buildFuture --quiet --destination "$TEMP/gal-test"
```

上が通ったうえで、以下をチェック:

- 生成HTMLに生のアスタリスク2個（`**`）が残っていない
- 生成HTMLに**未展開のショートコード**（`{{< hukidashi` がそのまま出てる等）が無い
- 内部リンクのリンク先が**実在する**
- `git diff` で **`aashi` に差分が無い**

## 🤖 サブエージェント並列指示テンプレ

```
あなたはギャル庁の記事加筆係です。以下のファイル**1本だけ**を加筆してください。
他のファイルは読むだけ（編集禁止）。

【対象ファイル】
site/content/posts/{slug}.md

【足すもの（水増し禁止）】
1. 前提知識・定義  2. 経緯・比較  3. 読者が行動できる情報
4. あーしの考察(insight) ＋ 過去記事への内部リンク3〜6本

【厳守】
- 数字・固有名詞・日付は WebSearch で裏取り。取れないものは書かない or 「〜とされてる」に弱める
- 記事の公開日より後の出来事は足さない。日付は絶対表記
- aashi は1文字も変更しない
- date / publishDate / categories / source / source_url は変更しない
- 強調で「」を囲むときは <strong>「…」</strong>（** の隣接バグ回避）
- 吹き出しは kasumi（硬いお役所口調・絵文字なし）と aashi のみ。kouhai 禁止
- 内部リンクは実在ファイルかつ**この記事より前に公開された記事**だけ
- アフィスニペットは入れない（<!-- AFFI: キーワード --> のみ）
- 本文の事実を直したら title / lead / points / tweet も整合させる
- 事実訂正したら記事末尾に「※YYYY年M月D日訂正：〜」を追記
- front matter に lastmod: {今日のJST} を追加（date は変えない）

【目安】本文 2,500〜3,500字。ただし字数のための水増しは禁止。
```
